# AGENTS.md

You're working on **Ants**: a VS Code extension that offers the user's Anthropic Console models (the **Claude (Console)** provider) to VS Code chat, Copilot agent sessions and the Agents window, signed in through the Anthropic profile that Claude Code or the `ant` CLI writes. No API key, no sign-in UI of its own. It also keeps a token-usage log with a drill-down panel.

[README.md](README.md) covers setup, the settings agent sessions need, and the limitations. Read it before changing behaviour users can see.

## Commands

```
npm ci                         # Node >= 22.13; installs the git hooks (lefthook)
npm run check                  # typecheck + lint + test: run before finishing
npm run typecheck              # tsc --noEmit
npm run lint                   # Biome (lint + format + import order); `npm run lint:fix` applies safe fixes
npm test                       # compiles, then runs test/run.mjs in a real VS Code against a fake Anthropic API
npm run package                # ants-<version>.vsix; `npm run test:vsix` tests that file instead of out/
npm run proposed-api           # re-downloads vscode.proposed.*.d.ts for the VS Code version named in the script
node scripts/release.mjs 0.2.0 # version bump + CHANGELOG + commit + tag; push the branch, then the tag (runs release.yml)
```

The test downloads VS Code into `.vscode-test/` on first run (on Linux, run it under `xvfb-run -a`) and writes everything else under `test/.scratch/`. It runs the suite twice, with and without the proposed APIs, and prints `test/.scratch/results.log` at the end. Set `VSCODE_VERSION` to test a specific release. The proposed-API pass starts with two groups in `chatLanguageModels.json` (active profile + a profile named `other`, whose fake workspace has the same `claude-test-1` as the first plus one model of its own, the way real organizations overlap); the other pass starts with none, like a fresh install, and writes the file mid-run (VS Code watches it), adding the named group later on. The fake API's `echo` reply names the workspace that answered, which is how the suite tells two groups' copies of one model apart. What the suite can't do is drive a Copilot agent session; `CONTRIBUTING.md` has the manual check for that. `ANTHROPIC_CONFIG_DIR` and `CLAUDE_CONFIG_DIR` point at scratch folders, so the suite never reads your own sign-in or Claude Code settings.

## Architecture

One TypeScript package, compiled with `tsc` to `out/` (CommonJS, `module: node16`), no bundler. The VSIX carries `node_modules/@anthropic-ai/sdk` with its ESM build, types and sources trimmed by `.vscodeignore`.

- `src/extension.ts`: `activate` and the `LanguageModelChatProvider`. Keeps one `Connection` (SDK client + resolved profile + identity) per profile the groups name, lists models from `/v1/models`, converts VS Code chat messages to the Messages API, streams text, thinking and tool calls back, reports usage, appends to the log. `effortSetting` and `contextSizeSetting` build the pickers.
- `src/identity.ts`: `anthropicConfigDir`, `activeProfileName` (the SDK's documented order: `ANTHROPIC_PROFILE`, `active_config`, `default`), `profilesOnDisk`, and `identityOf`, which reads the organization and workspace ids with the SDK's own `loadConfig` and the names from `GET /api/oauth/profile` (the endpoint Claude Code uses; undocumented, so a failure only means "no name"). `credentialsSavedAt` is the credentials file's mtime, never its contents.
- `src/status.ts`: the **Ants: Connection Status** command. Builds a Markdown page from the provider's `profileStatuses()` and shows it through an `ants:` text document content provider (Markdown preview when available, plain text otherwise). The command returns the Markdown, which the tests read.
- `src/onboarding.ts`: `signInHelp` (resolves the profile with the SDK's `loadConfig` and reads the *layout*, never a token, to explain why sign-in failed; names the profiles on disk when a group asks for one that isn't there; reads Claude Code's `.claude.json` from `CLAUDE_CONFIG_DIR` or home), `offerSetup` (one-time prompts for the agent-session settings and the proposed APIs, dismissals in `globalState.setupDismissed`), `offerFirstGroup` (one-time pointer to Manage Models when there is no group yet), `allowAgentSessions` (the command behind the Enable button). `explain` in `extension.ts` decides what gets sign-in help: connection errors are reported as unreachable hosts, API errors other than 401 are passed through as they are.
- `src/usageLog.ts`: `UsageRecord`, the price table (`PRICES`, dated), `estimateCost`, `sessionOf`/`surfaceOf`, and the `UsageLog` class over `usage.jsonl` in `globalStorageUri`.
- `src/usagePanel.ts` + `media/usage.{html,css,js}`: the **Ants: Show Claude Usage** webview. Plain DOM and SVG, VS Code theme variables, strict CSP with a nonce. The page gets records with `load` (plus `pricesAsOf`), single ones with `append`, and asks for `openLog` or `exportCsv` (sending the rows in view; `toCsv` in `usageLog.ts` writes them).
- `test/run.mjs` (fake API + VS Code launcher) and `test/suite.js` (runs inside the extension host; CommonJS on purpose).
- `vscode.proposed.chatProvider.d.ts`, `vscode.proposed.languageModelThinkingPart.d.ts`: typings for the proposals in `enabledApiProposals`, generated by `npm run proposed-api`.

## Invariants

- **Sign-in belongs to the SDK.** `new Anthropic()` resolves the active profile and `new Anthropic({ profile })` a named one; the SDK refreshes tokens, retries once on 401 and writes the new tokens back. Never read or cache tokens in the extension (`onboarding.ts` and `identity.ts` read the profile *layout* only). After a failure that profile's client is dropped so a later sign-in on disk is picked up without a reload; a cancelled request is not a failure.
- **Every model belongs to a Manage Models group; one group is one Anthropic profile.** The vendor declares a `configuration` schema with a single `profile` string, so VS Code calls `provideLanguageModelChatInformation` once per group with `{ configuration: { profile } }` and registers the models as `ants/<group>/<id>`. The groupless call VS Code also makes returns `[]` (answering it would list the active profile twice); VS Code makes it before the per-group calls, so the one-time "add the first group" offer waits a few seconds and is cancelled by any group call. A group with an empty profile is the active profile: `connect` re-reads `active_config` on every use, and when it has changed drops the client and fires `onDidChangeLanguageModelChatInformation` so the group's models are listed again. Never write `chatLanguageModels.json` from the extension; it is VS Code's file.
- **The usage log says who paid, and what happened.** Each record carries `organization` (name when the API gave one, else the id) and `workspace` (id) from the connection's identity, resolved after the first successful call. Stopped and failed requests are logged too, with `outcome`: a stopped one keeps the tokens that had arrived (output estimated from the streamed text, since the API only counts it at the end), a failed one has zeros and no cost. Fields are only ever added, and every new field is optional, so old logs keep loading.
- **Proposed APIs are optional.** `useProposedApi` is decided at runtime from `context.extension.packageJSON.enabledApiProposals`, which VS Code nulls when the user has not enabled them. Everything behind it (pickers, thinking parts, `configurationSchema`) must degrade to a working plain provider. Stable VS Code only honours the proposals with `--enable-proposed-api <publisher>.<name>` or the same entry in `argv.json`, which takes a full quit and relaunch.
- **Thinking is echoed verbatim.** Claude accepts earlier thinking only if each block comes back exactly as sent, `redacted_thinking` included. Metadata uses Copilot's keys (`signature`, `_completeThinking`, `redactedData`). On a prefix-mismatch 400 the request is retried once without thinking. `tool_choice: any` disables thinking.
- **Usage shape is what VS Code reads.** The `usage` data part is OpenAI-shaped (`prompt_tokens`, `completion_tokens`, `prompt_tokens_details.cached_tokens`). Costs are estimates from `PRICES`, dated by `PRICES_AS_OF`; say so wherever they are shown, and never show an unknown price as $0 (`estimateCost` returns `undefined`, the panel counts the request as unpriced and marks the total as a floor). Update `PRICES_AS_OF` whenever the table is checked.
- **The log never stores prompt text.** Sessions are identified by `modelOptions._conversationId` or a hash of the first user message.
- **Privacy.** No telemetry. The only network destination is the API the profile names. The webview renders values as text, never HTML.

## Conventions

- Tabs, single quotes, 120 columns, LF, UTF-8 (`.editorconfig`, Biome). Relative imports carry the `.js` suffix they compile to; `import type` for type-only imports. JSON files use two spaces because npm rewrites `package.json` that way.
- Every stable Biome group is on. Disabled rules are listed in `biome.jsonc` with a reason each. Suppress inline only per file or line with a reason (`// biome-ignore <rule>: why`); never silence a rule globally to make a finding go away. Review every `--unsafe` fix: it changes semantics.
- Prose, comments and error messages read like a person wrote them: short sentences, no jargon that the reader would not use, no exclamation marks. Comment only what needs explaining.
- `engines.vscode` is `^1.141.0`: Manage Models groups need 1.109 and the agent-session bridge 1.141, and the suite only ever runs on the current stable, so the floor stays close to it rather than claiming versions nobody tests. `@types/vscode` is the newest published at or below the floor (it lags VS Code by a release or two), and the proposed-API typings track the current VS Code (1.143, `npm run proposed-api`). Move all three together.
- No `Co-authored-by` trailers in commits. Subjects are plain sentences in the imperative or descriptive mood, like the existing history.
- Git hooks (`lefthook.yml`): Biome on staged files at commit, `npm run typecheck` at push. `LEFTHOOK=0` skips once. `npm ci --ignore-scripts` needs a manual `npx lefthook install`.
- Node policy: `engines.node` is the floor (22.13), `.node-version` and `@types/node` track it. Dependabot groups dev-tooling minors and patches; majors are taken deliberately. Actions are pinned to commit SHAs. `npm ci --ignore-scripts` in CI; no dependency may need an install script (`allowScripts`).
- Workflows: every checkout sets `persist-credentials: false` (nothing pushes), and no job uses the npm cache (`package-manager-cache: false`; a poisoned entry would end up in a VSIX, whether CI's artifact or a release). `zizmor` checks them (`uvx zizmor .github/workflows`; `zizmor.yml` runs it on changes under `.github/`, with `.github/zizmor.yml` requiring hash pins). CodeQL's default setup covers the TypeScript and the workflows. Branch rulesets on `main` require CI before a pull request merges and block force-pushes and deletion; the repository admin can push directly.
- Releases: `release.yml` has two jobs. `build` (read-only token, no npm cache) refuses a tag that isn't on `main` or `release/*`, doesn't match `package.json`, or hasn't passed CI, then builds the VSIX. `publish` runs no npm code: it downloads the artifact, attests its provenance, and creates the release, and it is the only job with `contents: write`. It waits in the `release` environment for the maintainer's approval. Releases are immutable (repository setting), so assets and tags are locked once published and GitHub signs a release attestation; users verify with `gh release verify-asset` and `gh attestation verify`. Keep the publish job free of third-party code.
- Patches come from `main`. Only when `main` carries unfinished work: `git switch -c release/0.2 v0.2.0`, cherry-pick the fix with `-x`, run the release script there, and add the new version's section to `main`'s changelog by hand afterwards. CI runs on `release/*` and the release workflow accepts tags on those branches.
- User-visible changes get a line under **Unreleased** in `CHANGELOG.md` and, where users would look for them, in `README.md`.

## Gotchas

- VS Code treats every model from an extension other than Copilot Chat as bring-your-own-key. Agent sessions see them only with `chat.agentHost.byokModels.enabled` (off by default in 1.141, on since 1.142; the agent host re-reads it live), and the Agents window runs only extensions listed in `extensions.supportAgentsWindow` (read at startup, so that one needs a restart). The bridge VS Code uses buffers the whole reply (no streaming), cannot cancel, hard-codes `cached_tokens: 0`, maps only `reasoningEffort` from `configurationSchema` (so `contextSize` is local-chat only), and passes `max_output_tokens` as `modelOptions.max_tokens`.
- `claude /login` → **Create an API key** stores the key inside Claude Code's own config, where the SDK's credential chain cannot see it. Only **Sign in with your Console account** writes the shared profile.
- Haiku 5.5 bills prompts over 100K tokens at five times the price; that is why its context picker starts at 100K.
- VS Code reads `argv.json` from `~/.vscode` even with a separate `--user-data-dir`. The test sets `VSCODE_PORTABLE` so the test instance cannot see the real one. Each pass uses its own portable folder: on Windows the previous VS Code can still hold `exthost.log` open for a moment after `runTests` returns, and deleting the folder then fails with `EBUSY`.
- Biome's `noProcessGlobal` fix inserts an ESM `import process from 'node:process'`, which breaks `test/suite.js` (CommonJS). The rule is off.
